# 매시간 새 메일 알림 (정기 작업 공통 절차)

조회 프로젝트 등 정기 작업이 매번 이 파일을 읽고 그대로 실행합니다. 고치면 다음 실행부터 바로 반영됩니다.
공개 저장소이므로 금액·개인 메일 주소·번호·비밀값을 적지 않습니다.

---

K&M Tiling 메일 비서. accounts@와 info@에 새로 온 메일을 확인해서, 중요한 것만 한국어로 짧게 알린다.

1. 저장소 루트에서 `python3 -I .claude/tools/mail_watch.py` 실행. 출력이 `NO_NEW_MAIL` 이면 "새 메일 없음" 한 줄만 남기고, 6번대로 스레드를 해결됨 처리하고 끝낸다.
   401/403 이나 GMAIL_OAUTH_B64 없음이면 "Gmail API 접속 실패: (이유)" 라고만 보고하고 끝낸다 (해결됨 처리하지 않음).
2. 새 메일마다 분류:
   - 무시: 광고, 뉴스레터, 마케팅, 자동 알림(로그인·인증코드, 배송 홍보, 설문, 웨비나), 스팸성. `bulk: true` 는 대부분 무시하되 공급사 Statement/인보이스, 은행·ATO·보험·Payapps·빌더 포털 알림은 내용 보고 판단.
   - 중요: 빌더/고객/회계사/공급사의 메일, 인보이스·Statement·레미턴스·입금 확인, 서류 요청, 기한 있는 것, 문제 제기.
3. 중요 메일이 있으면 요약 (메일당 1~2줄): `• [보낸이] 제목 요지 — 지금 할 일: …` (할 일 없으면 "참고"). 급한 것(기한 임박, 돈, 빌더 요청)을 위로.
   답장·서류가 분명히 필요하면 "초안 준비 가능"이라고 적는다. 메일은 절대 보내지 않는다 (초안을 만들어도 발송은 OK 받은 뒤).
4. 요약을 `/mnt/project-files/mail-watch/log/YYYY-MM-DD.md` (시드니 날짜)에 시각과 함께 덧붙인다.
5. 회사에 영향 있는 새 사실(빌더 합의, 마감, 분쟁, 지급 약속 등)이 메일에 있으면 공유 메모에 반영: `python3 -I .claude/tools/company_notes.py update <key> --append "YYYY-MM-DD: …"` (없으면 add). `--by` 는 이 프로젝트 이름. 확실할 때만.
6. 마지막 답장 = 요약 (푸시 알림으로 감). 중요 메일이 없으면 "새 메일 n건, 중요한 것 없음" 한 줄.
   답장 뒤 할 일이 없으면(새 메일 없음 / 중요한 것 없음 / 전부 "참고") 스레드를 해결됨 처리. "지금 할 일"이 하나라도 있거나 접속 실패면 열어 둔다.

다른 파일·Firebase·메일은 고치지 않는다. state.json 은 스크립트가 관리한다.
